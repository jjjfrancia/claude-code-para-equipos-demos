Preparar el entorno

Una sola vez. Los ejemplos 01 a 06 y 08 usan el Client SDK (anthropic); 07, 09, 10 y 11 usan el Claude Agent SDK, que trae el mismo motor de Claude Code.

pip install anthropic claude-agent-sdk pdfplumber
# Windows PowerShell:  $env:ANTHROPIC_API_KEY="sk-ant-..."
# macOS / Linux:       export ANTHROPIC_API_KEY="sk-ant-..."
cd "courses/Claude Code para equipos/demos/teoria"
python tutor_corpus.py "¿Cuánto dura el Daily Scrum?"     # comprueba el corpus, sin gastar API
💳 Cada corrida gasta tokens reales

Los programas imprimen los tokens y, en los del Agent SDK, el costo en USD. Los agentes llevan max_turns y max_budget_usd para que ninguna corrida se alargue. Los números cambian según el modelo y el momento: compáralos con lo que dice «Qué observar», no con cifras fijas.

Prompt chaining con gate

Building effective agents · «Workflow: Prompt chaining»

Tres llamadas en secuencia. Entre la segunda y la tercera, un gate por código rechaza la respuesta si no cita página o si cita una página que la búsqueda no devolvió.

1 · reformular (Haiku)→buscar→2 · redactar (Sonnet)→🚦 gate: ¿páginas válidas?→3 · adaptar a WhatsApp
Qué observarSi el gate dice RECHAZA, la cadena se detiene y nada llega al alumno. El gate no es un modelo: es una comparación de conjuntos.
En el TutorPasos fijos más un chequeo determinista: exactamente lo que pide la guía para tareas que se descomponen limpio.

Routing

Building effective agents · «Workflow: Routing»

Un clasificador rápido decide la categoría de cuatro mensajes distintos, y el código deriva cada uno a su camino: definición con Haiku, comparación con Sonnet, saludo y fuera de alcance sin modelo.

mensaje→🏷️ clasificador (Haiku)→definición · Haikucomparación · Sonnetsaludo · códigofuera de alcance · código
Qué observarLa pregunta sobre laptops nunca llega a la búsqueda ni al modelo grande. Ante una categoría desconocida, el código elige el camino más restrictivo.
En el TutorPrompts especializados por tipo de pregunta y el modelo pequeño para lo fácil: menos costo sin perder calidad.

Parallelization: sectioning y voting

Building effective agents · «Workflow: Parallelization»

Primero tres tareas independientes a la vez (redacción, términos clave, pregunta de repaso). Después, tres revisores con enfoques distintos votan si la redacción tiene información sin soporte.

párrafos→redaccióntérminosrepaso→🗳️ 3 votos→mayoría por código
Qué observarEl tiempo total en paralelo frente a la suma de las tres llamadas. Y que la decisión ENVIAR o BLOQUEAR la toma el código con 2 de 3 votos.
En el TutorEl guardrail va en una llamada separada: la guía indica que rinde mejor que pedirle a la misma llamada que responda y se vigile.

Orchestrator-workers

Building effective agents · «Workflow: Orchestrator-workers»

Una pregunta compuesta se parte en subpreguntas que decide el orquestador. Cada worker busca con su subpregunta y responde; un sintetizador une todo conservando las citas.

pregunta compuesta→🧭 orquestador → JSON→worker 1worker 2worker n→🧩 síntesis
Qué observarEl número de subpreguntas cambia con la pregunta. Cada worker recupera páginas distintas, y la síntesis las cita todas.
En el Tutor«Compara el PO y el Scrum Master en la Planning y la Review»: no se sabe de antemano cuántas búsquedas harán falta.

Evaluator-optimizer

Building effective agents · «Workflow: Evaluator-optimizer»

Un generador redacta y un evaluador lo critica en bucle, con tres criterios binarios. Dos los mide el código (longitud y páginas) y uno un modelo (afirmaciones sin soporte).

✍️ generador⇄🔍 evaluador: C1 · C2 · C3→APROBADO3 rondas → escalar a humano
Qué observarEl feedback de cada ronda y la condición de parada explícita: si no aprueba en tres rondas, la respuesta no se envía.
En el TutorHay criterio claro (cita, soporte, longitud del canal) y refinar mejora la respuesta de forma medible.

Prompt caching medido

API de Anthropic · Prompt caching · Claude Code · How Claude Code uses prompt caching

La Guía Scrum entera va como bloque del system prompt con cache_control. Se hacen dos preguntas seguidas y se imprimen los tres contadores de tokens de cada una.

tools→system→📚 documento · breakpoint|pregunta (cambia)

Guardrails contra prompt injection

Claude Code · Security · Agent SDK · Securely deploying AI agents · Hooks

Se simula un PDF malicioso: un fragmento que ordena crear un archivo y responder «Proyecto aprobado». Parte A delimita el texto con un nonce por petición. Parte B deja que los permisos permitan Bash y Write, pero un hook PreToolUse los bloquea siempre.

☠️ texto con instrucción→A · <datos-nonce> = DATOS→B · hook PreToolUse: deny→¿existe aprobado.txt? NO
Qué observarSi el modelo resiste solo, el hook no actúa y el programa lo dice. Si intenta Bash o Write, verás la línea BLOQUEADO. Al final se comprueba el disco.
En el TutorUna instrucción en CLAUDE.md es contexto; el hook es determinista. Lo que no debe pasar nunca va en el hook.

Memoria de sesión: resume y fork

Agent SDK · «Sessions and continuity» · Session management

Una primera consulta crea la sesión. La segunda la reanuda con su session_id y pregunta por lo dicho antes. La tercera la bifurca para explicarlo de otra forma sin tocar la original.

1 · nueva sesión→2 · resume=session_id→3 · fork_session=True
Qué observarEn la reanudación, el agente responde sin volver a buscar (tool calls = 0) porque el contexto se restauró. La rama del fork tiene otro session_id.
En el TutorUna sesión por alumno que se reanuda al siguiente mensaje de WhatsApp, en vez de empezar de cero cada vez.
